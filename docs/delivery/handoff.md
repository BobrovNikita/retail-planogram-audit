# Передача проекта и запуск на другом компьютере

Комплект рассчитан на локальную учебную демонстрацию в Windows. Это исходники с отдельной готовой ONNX-моделью, а не установщик Windows и не полностью автономный набор SDK/NuGet. На первом запуске нужны .NET SDK 10.0.400 из `global.json`, PowerShell и доступ к NuGet. GPU, Python, Git и Docker для получателя готового ZIP не обязательны. После успешного восстановления зависимостей и сборки демонстрация работает локально без интернета.

## Состав ZIP

- `START-HERE.md` — точка входа в комплект.
- `DELIVERY.json` — точный исходный коммит, состав и хэш архива модели.
- `SHA256SUMS` — SHA-256 всех остальных файлов комплекта.
- `RetailVision/` — исходники одного зафиксированного коммита с документацией, тестами и lock-файлами.
- `RetailVision-HoloSelecta-v2.zip` — проверенный архив весов, примера фото, иллюстраций, планограммы и описания источников.

В комплект не включаются `.git`, текущая база, учётные записи, пароли, пользовательские фотографии/аудиты, bin/obj, Python-окружение или Docker-образ. Тестовый синтетический ONNX внутри исходников предназначен только для тестов. Docker-комплект Linux распространяется отдельно и может иметь другой коммит; сверяйте его `COMMIT.txt`.

## Первый запуск

1. Полностью распакуйте ZIP, например в `C:\RetailVision-demo`. Не запускайте из окна просмотра архива. В этой папке должны лежать `RetailVision` и `RetailVision-HoloSelecta-v2.zip`.
2. Откройте PowerShell и выполните команды ниже. Путь можно заменить своим. Останавливайтесь при ошибке команды, не переходите к следующей.

```powershell
Set-Location 'C:\RetailVision-demo\RetailVision'
dotnet --version
dotnet restore --locked-mode
dotnet build -c Release --no-restore
dotnet run --project tools/RetailVision.DemoSetup -c Release --no-build -- '..\RetailVision-HoloSelecta-v2.zip' '..\retailvision-data'
```

`dotnet --version` из каталога проекта должен выбрать SDK, соответствующий `global.json`. Установщик создаёт **новую** папку `C:\RetailVision-demo\retailvision-data`. Родительская папка уже должна существовать; конечная — отсутствовать. Установщик откажется изменять существующую папку. Он проверяет архив, модель и CPU-инференс, затем создаёт чистую базу и товары. При диагностическом сбое сохраняет временную папку, действующие данные не удаляет.

3. Запустите приложение, задав свой идентификатор администратора:

```powershell
.\scripts\start-real-demo.ps1 -DataDirectory '..\retailvision-data' -AdminEmail 'demo-admin@example.invalid'
```

Адрес служит логином; отправки письма нет. Скрипт попросит придумать пароль скрытым вводом: минимум 12 символов, прописная и строчная буквы, цифра, специальный символ. Запомните его; в комплекте пароля нет. Существующему администратору повторный bootstrap пароль не меняет.

4. Откройте `http://localhost:5180`, войдите и проверьте «Настройки»: `holoselecta-snacks-v2-experimental`, восемь активных SKU. Для показа используйте [сценарий](demo-script.md). Фото лежит в `C:\RetailVision-demo\retailvision-data\sample\photo.jpg`.
5. Не ожидайте готовой истории: она появится после собственных запусков. После установки в каталоге 6 учебных и 8 HoloSelecta товаров; имеются учебная и контрольная планограммы. Полосы контрольного фото приведены в сценарии.

## Повторный запуск и остановка

Остановите сайт сочетанием Ctrl+C в его терминале. Для повторного запуска установщик и создание администратора не нужны:

```powershell
Set-Location 'C:\RetailVision-demo\RetailVision'
.\scripts\start-real-demo.ps1 -DataDirectory '..\retailvision-data'
```

Если порт занят, добавьте `-Port 5181` и откройте `http://localhost:5181`. Не запускайте два экземпляра с одной базой. Перед пересборкой остановите работающий сайт: Windows может блокировать DLL. Данные сохраняются в отдельной папке; не удаляйте её для обычного перезапуска.

## Частые ошибки

| Сообщение/ситуация | Решение |
|---|---|
| `dotnet` не найден или требуемый SDK не установлен | Установить .NET SDK указанной в global.json версии; одного runtime недостаточно. Переоткрыть терминал |
| NuGet недоступен | Первый restore требует сети и доступа к пакетам. Не считать комплект полностью автономным, пока restore/build не прошли |
| PowerShell блокирует скрипт | Проверить происхождение архива и локальную политику. Для доверенного скачанного файла при разрешённых правилах организации применить `Unblock-File` к конкретному скрипту. Не отключать глобально защиту выполнения |
| Установщик сообщает, что каталог существует | Для текущей базы сразу запускать start-real-demo.ps1; для новой установки выбрать другое имя, не удалять имеющиеся данные |
| Хэш/размер модели не совпадает | Повторно получить целый исходный архив HoloSelecta v2. Не редактировать manifest ради обхода проверки |
| `Address already in use` | Остановить свой прежний экземпляр либо выбрать другой порт |
| Не удаётся скопировать DLL при сборке | Остановить работающий RetailVision, повторить сборку, затем запустить его снова |
| Неверный пароль | Использовать пароль, заданный при первом bootstrap. Повторная передача AdminEmail пароль существующей записи не сбрасывает |
| «Нет модели» / отклонён контракт | Проверить запуск именно через start-real-demo.ps1 и выбранный каталог с setup.json и model/manifest.json; смотреть журнал терминала |
| Нет полок/неактивна кнопка распознавания | Выбрать правильную контрольную планограмму, заполнить все полосы и сохранить; проверить готовность модели |

## Контроль перед передачей

Для принимающего: сверить хэш ZIP с отдельным `.sha256`, распаковать, прочитать `DELIVERY.json`, установить в новую папку, проверить DEMO A/B/C и пройти один REAL-аудит, открыть историю и экспорт. Проверка нового компьютера считается выполненной только после такого запуска на нём. Существующие локальные и CI-протоколы не заменяют его.

Для сборщика: из чистого Git-репозитория, с Python 3.11+ и доступным Git, выполнить:

```powershell
python scripts/package-handoff.py --model-bundle 'C:\Artifacts\RetailVision-HoloSelecta-v2.zip' --output 'C:\Artifacts\RetailVision-defense.zip'
```

Скрипт не обучает модель и не обращается к сети. Берёт только `git archive HEAD`, отказывается от незакоммиченных/неотслеживаемых изменений, неверной модели или существующего результата. Добавляет manifest и хэши, проверяет CRC и SHA всех ZIP-записей, затем записывает внешний `.sha256`. Новые материалы сначала должны быть проверены и закоммичены; после этого архив отражает именно этот коммит.

Для публикации нужны отдельные параметры сервера. Локальный скрипт запускает Development HTTP только на localhost; это не настройка публичного HTTPS. См. [развёртывание](../deployment.md) и [обслуживание](../operations.md).
