# Краткое руководство пользователя

## Доступ и режимы

Откройте адрес запущенного экземпляра, обычно `http://localhost:5180`. Посетитель может просматривать каталог/планограммы и запускать DEMO. Для изменения данных, фотоаудита, истории и настроек войдите через `/account/login` с учётной записью, созданной при установке. Общего публичного пароля нет.

**DEMO** использует заранее заданные детекции и общий алгоритм сравнения. **REAL** получает детекции из ONNX-модели для вашей фотографии. Ручное исправление не превращает DEMO в REAL и не повышает исходную уверенность нейросети.

## Каталог товаров

1. Откройте «Каталог товаров». Используйте поиск, категорию, фильтр активности и режим карточек/таблицы.
2. Создайте товар или откройте редактирование. Заполните SKU, название, бренд, категорию, размер упаковки и активность. SKU содержит заглавные латинские буквы, цифры, `.`, `-`, `_` (до 64 символов).
3. При необходимости загрузите JPEG/PNG/WebP до 4 МБ, 4096 px по стороне и 4 мегапикселей. Фото проверяется и нормализуется. Публичным посетителям показывается нейтральная упаковка; загруженное изображение доступно администратору.
4. В «Классы моделей» задайте индекс только для действительно обученного класса соответствующей модели. Создание товара или назначение произвольного индекса не обучает детектор.
5. Сохраните. Связанный с другими данными товар обычно следует отключить; удалить его при существующих связях сервер не позволит. SKU связанного товара менять нельзя.

## Планограммы

1. В разделе «Планограммы» нажмите «+ Создать» либо «Дублировать» для существующей схемы.
2. Укажите название, магазин/зону и описание. Добавьте 1–10 полок.
3. Перетащите товары из каталога или добавьте кнопкой «+». Порядок можно менять мышью и стрелками; для другой полки используйте выбор полки.
4. Укажите число фейсингов — видимых экземпляров товара: 1–100 на позицию, всего до 500 в планограмме.
5. Нажмите «Сохранить» и дождитесь подтверждения версии. Откройте схему повторно, если нужно проверить сохранение.
6. «JSON ↓» выгружает схему; «Импорт JSON» создаёт новую копию из файла RetailVision schemaVersion 1 до 256 КБ. Все необходимые активные SKU должны уже быть в каталоге.

Изменение планограммы не меняет старые отчёты и фиксированные примеры DEMO. Для безопасного эксперимента работайте с копией. При конфликте версии HTTP 409 другой запрос уже изменил данные; несохранённые правки нужно перенести в актуальную версию вручную.

## DEMO-аудит

Откройте «Аудит витрины», выберите A «Правильная выкладка», B «Отсутствующий товар» или C «Нарушение порядка», нажмите «Запустить анализ». Ещё четыре сценария раскрываются ниже. Нажмите на нарушение, чтобы подсветить объект или ожидаемую позицию.

Ожидаемые основные показатели: A — 100%; B — 87,5%; C — 75% позиций и 87,5% LCS. Они характеризуют сравнение fixture-данных с эталоном, а не нейросеть. Администратор может отдельно сохранить DEMO в историю; анонимный запуск ничего туда не записывает.

## Анализ фотографии

1. Проверьте «Настройки»: модель подключена, нужные SKU присутствуют и активны. Параметры модели на этой странице показываются для контроля; замену модели выполняют конфигурацией сервера и перезапуском.
2. Откройте `/photoaudit` или ссылку «Ваша фотография витрины» со страницы аудита. Выберите планограмму и загрузите неподвижный JPEG/PNG/WebP: до 8 МБ, 6000 px по стороне и 12 мегапикселей.
3. Выберите полку справа и протяните прямоугольник на фото либо заполните границы в процентах. Полосы должны включать нижние опорные точки соответствующих товаров. Настройте все полки.
4. Оставьте порог 50% для воспроизводимой демонстрации. Нажмите «Сохранить границы», дождитесь подтверждения, затем «Распознать товары». Пока выполняется запрос, не запускайте его повторно.
5. После успешного REAL-анализа откроется сохранённый отчёт. Проверьте метку REAL, версию модели, рамки, нарушения и неопределённые случаи.

Черновик доступен 24 часа после загрузки. Сохранённый отчёт имеет собственную копию фото и от срока черновика не зависит. Отсутствие детекции не доказывает физическое отсутствие товара: проверьте фото, особенно для слабых классов. При сильной перспективе прямоугольные полосы могут быть недостаточны.

## Чтение отчёта

| Элемент | Значение |
|---|---|
| Зелёная рамка | Детекция сопоставлена с эталоном без нарушения |
| Жёлтая | Нарушение позиции/порядка |
| Красная | Несоответствие, требующее разбора |
| Серая | Неопределённость или ручная проверка |
| Позиции и порядок | Доля полностью правильных пар относительно максимума ожидаемых и обнаруженных объектов |
| LCS | Сохранение относительного порядка SKU |
| Наличие SKU | Доля подтверждённых уникальных ожидаемых SKU |
| Фейсинги | Согласованность количества по SKU и полке |

Для отсутствующего товара показывается ожидаемая позиция, а не искусственная рамка на фото. Процент соответствия конкретной выкладки и качество нейросети — разные величины. Формулы и крайние случаи приведены в [методике](../planogram-algorithm.md).

## Ручные исправления

В активном отчёте нажмите «Исправить детекции». Выберите объект, исправьте SKU/рамку или добавьте реально пропущенный объект. Подтвердите SKU и рамку вручную, укажите причину, сохраните пересчёт. Для ошибочного обнаружения доступно удаление детекции.

Система сохраняет исходные данные и журнал до/после. Ручное подтверждение — решение человека; исходная confidence не заменяется на «100% нейросети». Для возврата используйте действие восстановления исходных детекций; оно также записывается в журнал. Не исправляйте товары только ради увеличения процента.

## История, аналитика, экспорт и корзина

- «История проверок»: фильтруйте по датам UTC, режиму, названию/зоне и наличию правок. Выберите две записи для сравнения; различие моделей, порогов и эталонов требует осторожной интерпретации.
- «Аналитика» по умолчанию использует REAL. Дашборд показывает собственные активные REAL-отчёты. Новая база не имеет истории; пустое состояние нормально.
- «Скачать JSON» сохраняет структурированные исходные и текущие данные с журналом. «Печать / PDF» открывает печатный HTML; в диалоге браузера выберите сохранение в PDF.
- «В корзину» убирает отчёт из основной истории и аналитики. Откройте корзину и восстановите его, чтобы снова редактировать. Фото и журнал остаются.
- Защитный срок по умолчанию 30 дней. До его окончания окончательное удаление запрещено. После срока оно требует отдельного подтверждения; автоматическая очистка по умолчанию выключена.

Каталог и планограммы общие для администраторов; фотоаудиты, их изображения и отчёты доступны только владельцу. Для переноса всей базы используйте [резервное копирование](../deployment.md), а не JSON одного отчёта: экспорт отчёта не является резервной копией системы.
