# Следующая независимая проверка модели

Текущая v2 остаётся экспериментальной. Набор HoloSelecta из прежних 29 test-фото уже использован для анализа и теперь служит проверке регрессий. Его нельзя выдавать за новую независимую приёмку. Новые результаты без новых данных не заявляются.

До получения новых снимков подготовлены обучение, проверка разделения данных, validation, экспорт, PyTorch/ONNX parity и C# ModelProbe/evaluate_native.py. Эталон для будущей проверки — зафиксированный manifest v2 с SHA b359930eef08eeba01c50909704ff0a95fc7e45652a02d12d07ca7a1e818d8c2.

## Как организовать следующий этап

1. Зафиксировать восемь конкретных упаковок и назначение проверки. Другие размеры/дизайны упаковок нельзя автоматически считать тем же изученным SKU.
2. Собрать фотографии целевых полок с разными освещением, ракурсами, плотностью и перекрытиями. Нужны также пустые места и посторонние товары. Зафиксировать источник, разрешение на использование, автомат/магазин, дату и серию съёмки.
3. Разметить видимые товары и проверить неоднозначные классы вторым проходом. Особенно важны M&M’s и Twix. Полки/планограммы задавать по разметке, а не по ответам модели.
4. Разделить материал целыми локациями и сериями. Дубликаты, соседние кадры и производные одного изображения не должны попадать в разные split. Захэшировать и заморозить отдельный приёмочный набор до обучения/подбора порога.
5. До запуска согласовать минимально допустимые precision/recall по каждому SKU, правила частично видимых упаковок и предел времени на целевом CPU. Универсальный процент не устанавливается без цели использования и оценки последствий пропусков/ложных нарушений.
6. Сначала измерить v2 без изменений. Отдельно сообщить mAP, C# TP/FP/FN при заданном пороге, поклассовые P/R/F1, время и ошибки итогового аудита. Размер выборки и количество объектов каждого класса должны сопровождать проценты.
7. Улучшать модель по train/validation. Если результаты приёмочного набора использованы для выбора изменений, следующий независимый итог требует нового закрытого набора. Не подбирать порог по финальному test.

Для защиты курсовой можно показывать уже подготовленный пример и честно описанные ограничения. Для автоматического принятия решений на новых полках этих результатов пока недостаточно.
