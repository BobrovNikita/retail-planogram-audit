# Проверки

Локальная среда проверки: Windows, .NET SDK 10.0.400, runtime 10.0.11. Release build: 0 ошибок/предупреждений. EF не обнаруживает изменений модели после AuditHistory migration.

```sh
dotnet restore --locked-mode
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build --logger trx
```

105 unit-тестов: 74 проверки планограмм/анализа, 20 Vision и 11 ручной коррекции. Алгоритм покрывает все нарушения, повторяющиеся SKU, неопределённость, пороги, метрики, пустые/невалидные входы и 500 объектов; перебираются 600 пар коротких последовательностей с независимым LCS. Vision проверяет native ONNX inference на input-dependent синтетическом графе, RGB/NCHW и padding, обратные координаты у границы, EXIF-ориентацию, размер фото, низкую уверенность, ошибки тензоров, manifest/SHA/metadata и отказ тестовой модели в production-конструкторе. AuditReview проверяет неизменность исходной confidence, ручное подтверждение, добавление/удаление, недопустимые SKU/ID/рамки/числа и запрет выдавать ручную правку за исходную модельную детекцию.

83 интеграционных теста через WebApplicationFactory и настоящую временную SQLite: каталог, редактор, авторизация, миграции, отчёты, фото/калибровка и native ONNX → анализатор → HTML на явно синтетическом графе. История покрывает идемпотентное сохранение, копирование PNG, неизменные снимки, пересчёт и восстановление, журналы, SQL-фильтры/аналитику, сравнение, JSON/печатный HTML, CSRF, конфликт версий и изоляцию двух администраторов. Миграция проверяется с несколькими старыми аудитами. Пустые значения фильтра отправляются в тестах так же, как HTML-формой. Подготовленный REAL-вход в тесте хранения создаётся программно: это не проверка обученной модели. Тестовые пароли генерируются на запуск, временные папки удаляются после остановки приложения.

8 Python-тестов проверяют совпадение списка классов, корректность YOLO-разметки, отрицательные примеры, разбиение capture_id, дубли изображений между split и одинаковое разрешение пути датасета для проверки/обучения. В CI для них устанавливается только PyYAML; обучение и загрузка PyTorch не нужны.

HTTP smoke-test первого этапа: главная 200, /health — Healthy; desktop 1440px, mobile 390px, сценарий с пропуском 87,5% и подсветка ожидаемого слота.
