# Проверки

Локальная среда проверки: Windows, .NET SDK 10.0.400, runtime 10.0.11. Release build: 0 ошибок/предупреждений. EF не обнаруживает изменений модели после CatalogEditing migration.

```sh
dotnet restore --locked-mode
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build --logger trx
```

94 unit-теста: прежние 74 проверки планограмм/анализа и 20 проверок Vision. Алгоритм покрывает все нарушения, повторяющиеся SKU, неопределённость, пороги, метрики, пустые/невалидные входы и 500 объектов; перебираются 600 пар коротких последовательностей с независимым LCS. Vision проверяет native ONNX inference на input-dependent синтетическом графе, RGB/NCHW и padding, обратные координаты у границы, EXIF-ориентацию, размер фото, низкую уверенность, ошибки тензоров, manifest/SHA/metadata и отказ тестовой модели в production-конструкторе.

63 интеграционных теста через WebApplicationFactory и настоящую временную SQLite: прежние 54 проверки каталога, редактора, авторизации, миграций и отчётов; дополнительно фото, калибровка, CSRF, конфликты версий, отказ без модели, доступ владельца, лимиты/срок хранения и весь путь native ONNX → анализатор → HTML на явно синтетическом графе. Пересохранение калибровки удаляет старый результат. Тестовые пароли генерируются на запуск, временные папки удаляются после остановки приложения.

8 Python-тестов проверяют совпадение списка классов, корректность YOLO-разметки, отрицательные примеры, разбиение capture_id, дубли изображений между split и одинаковое разрешение пути датасета для проверки/обучения. В CI для них устанавливается только PyYAML; обучение и загрузка PyTorch не нужны.

HTTP smoke-test первого этапа: главная 200, /health — Healthy; desktop 1440px, mobile 390px, сценарий с пропуском 87,5% и подсветка ожидаемого слота.

Браузерная проверка второго этапа на отдельной временной БД: вход, создание товара и новой категории, поиск и таблица; дублирование планограммы, перестановка кнопками и реальным drag-and-drop, перенос между полками, добавление SKU, изменение фейсингов и сохранение с перезагрузкой. Проверена мобильная ширина 390px: страница не выходит за viewport, полки прокручиваются внутри. В консоли нет ошибок. Скриншоты planogram-editor.png и mobile-editor.png сохранены в docs/images. Выявленный случай потери значения фейсингов при немедленном сохранении исправлен и повторно проверен.
