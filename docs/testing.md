# Проверки

Локальная среда проверки: Windows, .NET SDK 10.0.400, runtime 10.0.11. Release build: 0 ошибок/предупреждений. EF не обнаруживает изменений модели после CatalogEditing migration.

```sh
dotnet restore --locked-mode
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build --logger trx
```

74 unit-теста: 20 проверок документа планограммы и 54 проверки анализа/fixtures. Покрываются все типы нарушений, повторяющиеся SKU, локальное сопоставление перед переносом между полками, геометрические допуски, нижняя опорная точка, неопределённая полка, null/неизвестный SKU, порог уверенности, метрики, пустые входы, базовая стратегия, разворачивание фейсингов, 18 невалидных входов и предельный размер 500 объектов. В одном тесте перебираются 600 пар коротких последовательностей с независимым рекурсивным LCS и проверкой однократного использования каждого ожидания/объекта.

54 интеграционных теста через WebApplicationFactory и настоящую временную SQLite: публичные страницы, семь DEMO-сценариев, вход, CSRF, seed и rate limiting; административные права, CRUD/архивация, занятый SKU/класс, конфликт версий, атомарное сохранение и перестановка позиций, JSON roundtrip/дублирование/удаление, неверный импорт, приватность и перекодирование JPEG в PNG, отказ SVG/слишком большим размерам, сохранение пустого каталога и миграция существующей базы. Проверки отчёта дополнительно сверяют метрики, число строк сопоставления, разделение неопределённости, цвета рамок, существование целей подсветки и вывод null SKU. Тестовые пароли генерируются на запуск, временные папки удаляются после остановки приложения.

HTTP smoke-test первого этапа: главная 200, /health — Healthy; desktop 1440px, mobile 390px, сценарий с пропуском 87,5% и подсветка ожидаемого слота.

Браузерная проверка второго этапа на отдельной временной БД: вход, создание товара и новой категории, поиск и таблица; дублирование планограммы, перестановка кнопками и реальным drag-and-drop, перенос между полками, добавление SKU, изменение фейсингов и сохранение с перезагрузкой. Проверена мобильная ширина 390px: страница не выходит за viewport, полки прокручиваются внутри. В консоли нет ошибок. Скриншоты planogram-editor.png и mobile-editor.png сохранены в docs/images. Выявленный случай потери значения фейсингов при немедленном сохранении исправлен и повторно проверен.

CI workflow выполняет те же сборку и тесты на Ubuntu, хранит TRX. Результаты для конкретного коммита доступны в GitHub Actions; наличие workflow само по себе не означает успешную проверку. Проверка Linux-контейнера, реального ONNX и нагрузочные испытания пока не выполнялись.
