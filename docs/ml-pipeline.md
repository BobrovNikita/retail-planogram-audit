# Компьютерное зрение: состояние после этапа 3

Сейчас реализован только `FixtureProductDetector`. Он принимает один из семи известных идентификаторов, возвращает фиксированные нормализованные рамки/полки/SKU и метаданные `DEMO`, `fixture-v2`. Значения confidence=1 и confidence=0,2 в сценарии uncertain — предопределённые записи для проверки алгоритма, а не измеренная уверенность нейросети. Анализатор уже принимает геометрию полок, но пользовательская калибровка фотографии ещё не реализована.

Реального OnnxProductDetector, весов, обучения, парсера тензора и оценки точности пока нет. Интерфейс и отдельный проект Vision позволяют подключить это на этапе 4. Нельзя подавать произвольную фотографию в fixture или считать COCO bottle распознаванием конкретного SKU.

Следующий контракт модели должен фиксировать: версию и SHA-256 весов, входное имя/shape/layout, нормализацию, letterbox/padding, выходные имена/shape, формат координат, end-to-end/NMS, словарь classIndex→SKU. Парсер должен быть написан по фактическому экспортированному ONNX-графу YOLO26n, а не предположению о формате всех YOLO.

План: Python train/validate/export, разбиение по независимым съёмкам без утечки похожих кадров, сравнение PyTorch и ONNX на одинаковом наборе, CPU-инференс из C#, проверка magic bytes/размеров изображения до полной декомпрессии, ручные нормализованные границы полок с использованием нижней опорной точки товара. На production Python не потребуется. Ни mAP, ни precision/recall, ни latency до измерений не публикуются.
