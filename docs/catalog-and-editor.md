# Каталог и редактор планограмм

Для изменения данных войдите администратором. Публичный пользователь просматривает активные товары и планограммы и запускает фиксированные DEMO-сценарии.

## Каталог

В карточке задаются SKU, название, бренд, категория, размер упаковки, нейтральный цвет и активность. Можно выбрать существующую категорию или создать новую. SKU состоит из заглавных латинских букв, цифр, точки, дефиса и подчёркивания, до 64 символов. SKU связанного товара менять нельзя. Дата создания сохраняется в UTC.

В секции «Классы моделей» указывается индекс класса для каждой существующей версии модели. Пустое поле снимает связь. Один класс нельзя назначить двум товарам; ProductId и ClassIndex независимы. Управление версиями ONNX-моделей появится позже.

Изображения JPEG/PNG/WebP: до 4 МБ, до 4096 px по стороне и до 4 мегапикселей. Проверяется содержимое, а не расширение. Анимации и повреждённые данные отклоняются. EXIF-ориентация применяется, изображение уменьшается до 1200 px по большей стороне и перекодируется в PNG без исходных метаданных. Имя — случайный серверный ключ. Файлы доступны только администратору; публичная карточка показывает нейтральную SVG-упаковку.

Удаление доступно для товара без ссылок из позиций, классов модели и детекций. Связанный товар можно отключить: он останется в существующих планограммах и исчезнет из выбора новых товаров. Фильтры включают строку поиска, категорию, активность; доступны карточки и таблица.

## Редактор

1. Создайте планограмму, укажите название, магазин/зону и описание.
2. Добавьте нужные полки. Всего 1–10 полок; удалить можно только пустую, оставшиеся перенумеруются.
3. Перетащите товар из каталога или выберите целевую полку и нажмите «+».
4. Меняйте порядок мышью либо стрелками. Выпадающий список переносит позицию на другую полку.
5. Задайте фейсинги: 1–100 на позицию, до 100 позиций на полку и до 500 фейсингов в планограмме.
6. Нажмите «Сохранить». Подтверждение показывает новую версию. При конфликте версии правки остаются в редакторе; откройте актуальную планограмму в другом окне и перенесите нужные изменения.

Пустая полка допустима. Товары представлены упорядоченными карточками с SKU и количеством фейсингов. На телефоне полки прокручиваются по горизонтали, перемещения доступны кнопками и выбором полки.

Список планограмм позволяет создать независимую копию, экспортировать JSON или удалить планограмму без связанных аудитов. Копирование и импорт требуют активных SKU; сначала включите товары, если исходная схема содержит отключённые. Существующая планограмма допускает сохранение уже присутствующих в ней неактивных SKU.

## JSON schemaVersion 1

Экспорт не содержит ID базы данных или путей к изображениям. Пример:

~~~json
{
  "schemaVersion": 1,
  "name": "Напитки у кассы",
  "description": "",
  "store": "Зона А",
  "shelves": [
    {
      "number": 1,
      "slots": [
        { "position": 1, "sku": "RV-COLA", "facings": 2 },
        { "position": 2, "sku": "RV-LIME", "facings": 1 }
      ]
    }
  ]
}
~~~

Импорт: UTF-8 JSON до 256 КБ, глубина до 16. Неизвестные поля, неподдерживаемая версия, несуществующие/неактивные SKU, дубликаты и пропуски порядковых номеров отклоняются без частичной записи. Номера полок и позиций начинаются с 1. Сначала перенесите необходимые SKU в каталог. Импорт всегда создаёт новую запись и не перезаписывает исходную планограмму.

Сохранение через Fetch передаёт анти-CSRF токен. HTTP 422 означает ошибки документа, 409 — конфликт версии/связей. При сетевой ошибке локальные правки остаются в открытой вкладке, но не восстанавливаются после её закрытия. Сохранённые изменения находятся в SQLite.

DEMO использует отдельную фиксированную планограмму. Проверка собственной фотографии по созданному эталону требует следующих этапов детектора и истории аудитов.
