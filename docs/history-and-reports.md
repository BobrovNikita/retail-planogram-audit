# История, отчёты и ручная проверка

Этап 5 реализован 2026-10-25. История доступна администратору через /history. Каждая запись, фотография, JSON, печатная страница и действие коррекции проверяют OwnerId. Другой администратор не получает доступ к чужому отчёту; публичный дашборд не раскрывает данные владельцев.

## Сохранение

Успешный REAL-анализ автоматически сохраняет отчёт и открывает его. Копия нормализованного PNG хранится в Storage:DataDirectory/audit-photos, отдельно от временного photo-drafts. Удаление или истечение черновика не удаляет отчёт. Для результата из ранее созданного черновика есть кнопка сохранения. Повторный POST с той же парой draft ID/revision возвращает прежний отчёт, а не создаёт дубль.

Без обученной модели реальный анализ недоступен. DEMO можно сохранить отдельной кнопкой из результата после входа администратором. Публичный посетитель не записывает данные. Учебный отчёт всегда остаётся DEMO, даже после ручных исправлений; TEST-граф не сохраняется через пользовательские маршруты.

SQLite хранит время UTC, владельца, снимок планограммы и её версию, названия SKU, исходные детекции/результат, геометрию полок, пороги, размеры изображения, режим, версию/SHA модели, текущие детекции и все метрики. Фото находится в закрытом каталоге, в БД — только его случайный ключ. Изменение каталога или планограммы не переписывает сохранённые отчёты.

## Ручная коррекция

В отчёте нажмите «Исправить детекции». Выберите объект в списке, поменяйте SKU, перерисуйте рамку на изображении или укажите нормализованные координаты в процентах. Можно добавить пропущенный объект или удалить лишнюю детекцию. Номер полки вычисляется по нижней опорной точке; вне полос объект остаётся неопределённым.

Изменённые и новые объекты требуют флага «Подтверждаю SKU и рамку вручную». Это решение человека, а не уверенность модели: исходная confidence не меняется, а новые объекты не имеют модельной оценки. Для сопоставления подтверждённый объект получает эффективную confidence = 1. В JSON текущий объект содержит confirmedByHuman и effective; оригинальная оценка находится в detection.confidence и неизменном snapshot.originalDetection. В HTML ручное решение подписано словами, без ложных «100% AI».

Обязательна причина до 1000 символов. Сервер проверяет SKU по сохранённому каталогу, уникальность ID, границы/конечность чисел и лимит 500 объектов. Подменить confidence через запрос нельзя. Несохранённые правки предупреждают при уходе со страницы.

Сохранение атомарно обновляет текущие детекции, нарушения, метрики и добавляет AuditCorrection: автор, UTC, редакция, причина и полный JSON до/после. Revision — EF concurrency token; устаревшая вкладка получает HTTP 409 и не перезаписывает правки. Восстановление исходных детекций создаёт новую запись журнала и пересчитывает результат. Журнал не удаляется и не меняет режим проверки.

## История и аналитика

История выводит по 20 записей: даты включительно по UTC, режим REAL/DEMO, название планограммы/торговой зоны и наличие правок. Выберите две записи для сравнения текущих значений и разницы в процентных пунктах. Разные эталоны, режимы, модели или пороги помечаются как несопоставимые условия.

Аналитика по умолчанию фильтрует REAL. При выборе DEMO или всех режимов показывается предупреждение. Среднее — арифметическое по последним редакциям сохранённых проверок; до 60 последних дат с данными показаны отдельно. Фильтр «Есть исправления» учитывает любую запись журнала, в том числе восстановление. Дашборд показывает только собственные REAL-записи, до 14 дат и пять последних проверок. Без данных отображается пустое состояние. Метрики соответствия не являются точностью распознавания.

## Экспорт и печать

«Скачать JSON» возвращает schemaVersion=1: метаданные, snapshot, current, result и corrections с состояниями до/после. В экспорт не включаются пароль, внутренний путь диска или ключ хранилища фотографии. imageUrl требует авторизации владельца.

«Печать / PDF» открывает отдельный HTML-отчёт /history/print/{id}: фото/учебная иллюстрация, рамки, ожидаемые позиции, таблица сопоставления, метрики по полкам и журнал. Кнопка печати вызывает стандартный диалог браузера; для файла выберите «Сохранить как PDF». Серверная генерация PDF не выполняется. Печатное представление использует тот же AuditReport и partial, чтобы в дальнейшем можно было добавить серверный renderer без повторного расчёта аудита.

## Хранение и ограничения

Постоянные отчёты автоматически не удаляются. Контролируйте место на диске; интерфейс удаления архива и политика срока хранения пока отсутствуют. Резервировать нужно всю SQLite-базу вместе с keys/, product-images/, photo-drafts/ и audit-photos/. Запуск рассчитан на один процесс. Запись PNG и транзакция SQLite — разные операции: при обычной ошибке новый PNG удаляется, аварийное завершение между операциями может оставить файл без ссылки; отчёты сами по себе не чистятся.

Миграция AuditHistory сохраняет прежние записи, расширяет Audit/AuditCorrection и делает ссылку на Planogram необязательной для фиксированного DEMO. Старые служебные записи без OwnerId автоматически никому не назначаются и не показываются в пользовательской истории. Их исходные столбцы остаются в БД. Перед обновлением делайте резервную копию; откат — восстановление всей копии, а не удаление данных вручную.
